## Root causes

Each was re-read in the code or the data for this spec. Claims marked "checked" were re-checked by the designer.

### Consumables (ask 1, 2)

- **C1. Outside a ready check the bar only asks for habits (checked).** Buffs.lua:1233-1234 walk `habitsDB()` (your past
  uses), not your bags: `for id, e in pairs(h) do` / `if type(e) == "table" and (e.hits or 0) >= 2 and bags[id] and n < 3`.
  An elixir you carry but have not drunk twice since install is never asked.
- **C2. A use in a fight is never counted (checked).** Buffs.lua:1431-1432: `lastUse.at, ... = A.Now(), sp, nil` then
  `if A.Fighting() then return end`, before `pending[id] = A.Now()` (1436). A tank who drinks between pulls while still in
  combat never builds the habit.
- **C3. Carried items that are not habits are asked only Before the pull (checked).** Buffs.lua:1359
  `if not ctx.pull or A.Settings().consume == "off" then return end`. That runs on READY_CHECK or on entering a raid
  (Bar.lua:932, 937-938), never on entering a 5-man. Stratholme with no ready check asks nothing.
- **C4. Before the pull filters by role, and a paladin can read as a healer.** Buffs.lua:1384
  `(habit or (PULL_SUB[sub or -1] and Bf.Fits(id, role)))`; Roster.lua:97-100 falls back to `R.CLASS_ROLE[class]`, and
  Roster.lua:26 has `PALADIN = "healer"`. A tank paladin whose spec cannot be read is offered no Strength or Agility
  elixir. Whether this happens live is unknown: the new diag line prints the role, where it came from and the spec.
  0.2.3 no longer lets a role that is only the class's guess hide anything (1.3).
- **C5. One switch for everything.** Window.lua:171 `choice(p, x1, -340, "Potions, elixirs, flasks and Well Fed", { always,
  instance, pull, off })`. No per-item or per-content choice exists. Potions are never asked Before the pull unless a habit:
  Buffs.lua:1349 `PULL_SUB = { [3] = 1, [2] = 2, [4] = 3 }` (no subclass 1).
- **C6. Nothing is asked in a city or inn, and the default asks nothing in the open world.** Core.lua:126
  `consume = "instance"`; Buffs.lua:1194-1195 `if mode == "off" or ctx.town then return false end`. Nothing tells the
  player why.
- **C7. Two Never keys for one item, both on a moving root.** Buffs.lua:1261 `"consume:" .. g` and Buffs.lua:1418
  `"flask:" .. g`; groupOf (1138) re-roots when a lower id joins (1149). A Never can stop matching, and hides the partner.
- **C8. A battleground counts as a 5-man.** Bar.lua:95 `return plain(kind) == "raid" and "raid" or "party"`.
  Gear.lua:126-132 `G.Context()` already tells pvp apart.
- **C9. A missing item answer is kept for the session.** Buffs.lua:305-316 store `false` in `itemAuraOf` when
  `C_Item.GetItemSpell` answers nothing (ItemDocumentation.lua:970-972 `MayReturnNothing = true`). A server-sent item read
  before the client has it can never count.
- **C10. Lasting-buff items outside subclasses 1-4 are left out.** gen_data.py:341-342 keeps class 0 subclasses 1-4 and
  class 12. Spirit of Zanza (Item.csv `20079,0,8`) and Rumsey Rum Black Label (`21151,0,5`, Stamina 15 min) have no entry.

Not causes (checked): Forever keeps Classic's subclasses (Item.csv 71037: `13452,0,2` Mongoose, `13510,0,3` Titans,
`13455,0,1` Stoneshield, `10305,0,4` Scroll of Protection IV, and Forever's own `250334,0,2` Elixir of Fortitude,
`274274,0,3` Flask of Natural Aggression). Forever has no Battle or Guardian elixir data: `grep -ci "battle elixir\|guardian
elixir"` gives 0 in ItemSparse.csv and SpellName.csv (71037). Flasks say so in their own text: Spell.csv 17626 "You can
only have the effect of one flask at a time", and the same on Forever's 1293740-1293743.

## 1. Consumables

### 1.1 Where you are

`Cn.Where()` returns `A.Gear.Context()`: `"solo"`, `"pvp"`, `"dungeon"` or `"raid"` (Gear.lua:126-132, unchanged). The
bar's `readAll()` (Bar.lua:636) sets `ctx.where = Cn.Where()`. `ctx.inst` stays as it is for its other users.

| Key | Chip word | Place words (tooltips) |
|---|---|---|
| solo | World | the open world |
| pvp | PvP | battlegrounds and arenas |
| dungeon | 5-man | 5-man dungeons |
| raid | Raid | raids |

The biome gear chips use the same words: Window.lua's `CTX` label "Solo" becomes "World" and its tip "solo play" becomes
"the open world"; its defaults label "New pieces show in:" (Window.lua:436) becomes "By default:", as on the Consumables
tab. Gear.lua:24 `G.CONTEXTS` labels ("Solo content", "PvP content", "5-man content", "Raiding content") become World,
PvP, 5-man, Raid, so the gear icon's right-click (Gear.lua:655-665, title "Show it in") and a consumable's (1.14) name
the same places with the same words. Saved keys stay `solo`.

### 1.2 Kinds

`Cn.KindOf(id)` returns `kind, word` from `C_Item.GetItemInfoInstant`'s class and subclass, and the use spell
(`Bf.ItemAura(id)`). Order on the tab and in the bar: the table's order.

| Kind | Items | Bar word | On by default in |
|---|---|---|---|
| `fed` | the Well Fed row (key `"fed"`, not an item) | Eat | World, 5-man, Raid |
| `flask` | class 0, subclass 3 | Drink | Raid |
| `elixir` | class 0, subclass 2 | Drink | 5-man, Raid |
| `potion` | class 0, subclass 1 | Drink | nowhere |
| `scroll` | class 0, subclass 4 | Read | Raid |
| `other` | class 12, or class 0 subclass 0, 5 or 8, when `Cn.Words(id)` is not empty | Use | Raid |
| `weapon` | any item whose use spell is in `D.IMBUE` | Apply | nowhere |

- An item counts only when its use spell is known and either has stat words (`Cn.Words(id) ~= ""`) or has been used with
  a lasting aura (`hits >= 1`). A healing potion (words `""`, never a lasting aura) never gets a row and is never asked
  (question 2).
- `Cn.Words(id)`: D.CONSUME[spell], else the words read from the spell's text as Buffs.lua does today for server-sent
  items. `other` reads `Cn.Words`, never D.CONSUME alone, so a server-sent juju the tables lack still gets a row.
- `Cn.KindOf` tests `weapon` first (its use spell in `D.IMBUE`), then the class and subclass rows, `other` last: an oil
  or a poison is never `other`.
- Well Fed foods (D.FOOD) are never `other`: the camp and the Well Fed row cover them.
- `Bf.KindOf` keeps its 0.2.2 answer, the bar word and the subclass (harness.lua:2187 expects "Use" for a juju).
  `Bf.GroupOf`, `Bf.AuraOn`, `Bf.Fits` stay as aliases (the harness calls them).

### 1.3 The one decision: `Cn.AsksIn(id, where)`

Returns `asks, reason`. The bar, Before the pull, the tab's chips and the diag all use it. It does not read the master
switch (`Cn.On()`); the providers do.

1. `B.Never(neverKey(id))`: `false, "never"`. neverKey is `"consume:" .. id`, and `"eat"` for `"fed"`.
2. The item's own choice for `where` (`items[id][where] ~= nil`): that value, reason `"chosen"` or `"off"`.
3. A habit (`A.Char().consume[id].hits >= 2`) in a place where habits are asked: `true, "habit"`. `consumables.habits`
   names those places: `"inst"` (the default) PvP, 5-man and Raid, where 0.2.2's Instances asked any habit of any kind
   (Buffs.lua:1192-1196, 1233-1234; a battleground counted as an instance, Bar.lua:95); `"world"` the open world too
   (0.2.2's Always); `"pull"` none, so habits are asked only before the pull (0.2.2's Ready check). Anywhere else, go on.
4. Its kind's default for `where` is false: `false, "off"`.
5. `fed` or `weapon`: `true, "default"`.
6. Quiet (`A.Char().consumeQuiet[id]`, section 1.8): `false, "unused"`.
7. `Cn.Fits(id)`: `true, "fit"`; else `false, "role"`.

A habit comes before its kind's default, so what you already use keeps being asked: a Greater Stoneshield habit in a raid
(potions default to nowhere), a flask habit in a 5-man (flasks default to Raid).

`Cn.Fits(id)` (fixes C4):

- `R.MyRole()` gains a third return, where the role came from: `"choice"` (Settings, Your role; Roster.lua:93),
  `"group"` (the group's tank or healer mark, :96, or its damage mark, :99), `"talents"` (:97), `"class"` (:100, the
  class's guess: Roster.lua:26 `PALADIN = "healer"`). Comm.lua:142 reads the first two and does not change.
- From `"class"`: every item with stat words fits (`Cn.Words(id) ~= ""`). A guess never hides an item, so a tank paladin
  whose talents cannot be read is still asked for the Mongoose or Elixir of Giants.
- An `other` item whose words hold `sta` fits every role: Spirit of Zanza is "spi sta", and fitsWords alone gives a
  melee or a tank false for its Spirit (Buffs.lua:1281, 1283, 1288).
- Else `Bf.Fits(id, role)`, as today.

### 1.4 Your part of the bar (provider `consume`, order 120)

Runs when `Cn.On()`, out of a fight, `not ctx.town` (IsResting) and `not ctx.pull`.

- Candidates: every item in your bags (`B.Bags()`) with a kind other than `weapon`, plus habits you carry.
- Asked when `AsksIn(id, ctx.where)` is true and its buff is missing, or on you with under 60 s left (then its countdown,
  status warn).
- While the item's cooldown runs (`S.ItemCD(id)`, Spells.lua:217), the record carries `rec.cdStart`, `rec.cdDur` (the
  sweep L.Paint already draws, Look.lua:136-138) and `rec.lit = false`, and the bar wakes at its end. Every potion shares
  one cooldown (ItemEffect.csv 71037 row 99538, item 13455 by ItemXItemEffect: CategoryCoolDownMSec 120000,
  SpellCategoryID 4), so after a healing potion a Stoneshield is shown waiting, not asked to be drunk.
- One icon per group (1.7). A group with a member's buff on (60 s or more left) asks nothing.
- At most 3 icons. Order: reason chosen, then habit, then fit/default; then the one used last (`e.at`); then flask,
  elixir, scroll, potion, other; then the lowest id.
- Record: key `"consume" .. id`, word from 1.2, click `B.Click(rec, "item", id, "player")`, Never `"consume:" .. id`,
  neverName the item's name. `rec.why`: "You keep this one up." (habit), "You chose it for here." (chosen), "It fits your
  role." (fit), "Its buff ends soon." (countdown).
- Habit learning stays: two uses with a lasting aura make a habit. **A use in a fight now counts** (C2): `onCast` sets
  `pending[id]` before the fight check. A use made in a fight waits for the first read that can see your auras: its 6 s
  expiry (Buffs.lua:1179) counts from the fight's end, not from the use. Only the bar's refresh waits for the fight.

### 1.5 Well Fed

- World: the camp's Eat (Camp.lua:669-671) also returns when `Cn.On() and not Cn.AsksIn("fed", "solo")`. With
  consumables Off it follows only Camp, as in 0.2.2 (it never read the old setting).
- PvP, 5-man, Raid: Eat (`Camp.BestFood(true)`) when `Cn.On()`, you are not Well Fed and `AsksIn("fed", where)`.
- The countdown, under 2 minutes left: wherever you are out of town, while `Cn.On()` and Well Fed is not on Never,
  whatever its chips. 0.2.2 ran it in every mode but Off (Buffs.lua:1203, 1213), so a Ready check save keeps it.
- Key `"food"`, Never `"eat"` (unchanged). `"eat"` also hides the camp's Eat (its record sets no `never`, so its key is
  `"eat"`) and, new, the pull's food (1.6).

### 1.6 Before the pull (provider `pull`, order 300)

Unchanged, with these changes:

- It runs only when `Cn.On()` (replaces `A.Settings().consume == "off"`, Buffs.lua:1359).
- An item with its own choice for here follows it: on is asked whatever its kind (potions too); off is never asked.
- Fit is `Cn.Fits(id)` (1.3), so a guessed role hides nothing here either.
- Never: `"consume:" .. id` hides it here as everywhere; `"pull:" .. id` hides it here only (what a 0.2.2 `flask:<g>`
  Never becomes, 1.11). The icon's own Never sets `"consume:" .. id`.
- The food also needs `not B.Never("eat")`: Well Fed's Never chip says "not even before the pull". Its own `"pullfood"`
  Never (Buffs.lua:1375) still hides only this food.
- An item on cooldown is drawn waiting, as in 1.4.

Food first, then at most 4 items, flasks first, cover at 180 s, as today. Kind defaults, quiet and `habits` do not limit
it: a ready check still asks every fitting flask, elixir and scroll, and every habit.

### 1.7 Groups (items that replace each other)

An item's group keys, all checked:

| Key | Source |
|---|---|
| learned root | `groupOf(id)` from account pairs (as today, Buffs.lua:1131-1150) |
| kin | `kind .. ":" .. first word of Cn.Words(id)`: Mongoose ("agi crit") and Greater Agility ("agi") share `elixir:agi` |
| `flask` | every flask (the client's own text: one flask at a time) |

- Only one member of a group is asked per read: the first in the order of 1.4.
- Two members' auras seen on you at once let that key go, collected first and set after the walk:
  - learned: `pairsDB()[member] = nil` for each member of that group;
  - kin: `A.Acct().kinStacks[kinKey] = true`;
  - flask: `A.Acct().flasksStack = true`.

### 1.8 Quiet (an unused fit stops asking)

- A `habit` or `fit` item counts a miss after 600 s **on screen**, unused. 0.2.2 counts wall-clock time since it was first
  asked (Buffs.lua:1241-1248, `ASK_FOR = 600` at Buffs.lua:39), but your part of the bar hides in every fight (Bar.lua:208
  `[combat] hide; show`): a tank chain-pulling Stratholme sees the elixir a minute between pulls and would lose it for
  good in about half an hour.
- Bar.lua keeps `B.ShownFor(key)`: on each clock tick it adds the seconds since the last tick to every laid-out record
  while its part is visible (`own:IsVisible()`: false in a fight, while the bar is away or off). The provider keeps
  `missFrom[id]`, the ShownFor at the last miss or use; a miss when `ShownFor - missFrom >= 600`; it wakes at
  `t + 600 - (ShownFor - missFrom)`.
- Three misses: `A.Char().consumeQuiet[id] = time()`. 60 kept; the oldest goes first. A habit still loses its habit at
  three misses, as today.
- A use of the item, or any chip click on its row, clears `consumeQuiet[id]`.
- A `chosen` or `default` item (Well Fed, a weapon) is never quieted. Before the pull ignores quiet.

### 1.9 Weapon

The weapon provider (Buffs.lua:334) first looks at the main hand (slot 16) when `tempEnchant(16) == false`. Of the
carried `weapon` items with `AsksIn(id, ctx.where)` true, the one chosen for here, else the one used last (`e.at`), else
the lowest id (`B.Bags()` is walked with pairs, which has no order) gives rec key `"weapon16"`, word Apply, item click with
target slot 16, name "Your weapon", why "Nothing on it: you chose this for here." Otherwise it uses the per-weapon habit
as today.
There is never more than one icon per slot. Off-hand items are not in the tab (Out of scope).

### 1.11 Saved keys and migration

| Key | Where | Shape |
|---|---|---|
| `consumables` | `A.Settings()` (account) | `{ on = true, habits = "inst", kinds = { [kind] = { solo, pvp, dungeon, raid } }, items = { [id or "fed"] = { solo, pvp, dungeon, raid } } }` |
| `consumeQuiet` | `A.Char()` | `{ [id] = time }` |
| `kinStacks`, `flasksStack` | `A.Acct()` | `{ [kinKey] = true }`, boolean |

- `kinds` holds explicit booleans for every kind and place (no nil). `items[id][where]` is nil (no choice) or a boolean.
- `habits` is a string, `"inst"`, `"world"` or `"pull"` (1.3), never a boolean. No widget shows it; the diag prints it.
- `Cn.Settings()` builds the table when it is missing. It is not in `A.DEFAULTS`: copyDefaults would share one table.
- Never write `ok and plain(v) or nil` for these booleans.

Migration, once, in `A.Settings()` before copyDefaults, when `s.consume ~= nil`:

| 0.2.2 `s.consume` | 0.2.3 | What stays as it was |
|---|---|---|
| `"instance"` (the default every save holds, Core.lua:126) | the defaults of 1.2, `habits = "inst"` | habits of any kind asked in every instance (1.3 step 3); Well Fed's countdown everywhere |
| `"always"` | the defaults, `habits = "world"` | habits asked in the open world too, and only habits there (Buffs.lua:1196, 1233-1234): no kind is turned on for the world |
| `"pull"` | every kind off in every place except `fed` World, `habits = "pull"` | nothing asked in an instance but Well Fed's countdown (1.5; Buffs.lua:1203, 1213); Before the pull unchanged |
| `"off"` | `on = false`, `habits = "inst"` | the camp's Eat in the world (it never read this setting, 1.5) |

Then `s.consume = nil`. `consume = "instance"` leaves `A.DEFAULTS`, so copyDefaults never puts it back.

Never keys: collect every `"flask:<g>"` and `"consume:<g>"` key first, then for each write one key for every member m of
g's learned group (g alone when it has none), and remove the old key:

- `"flask:<g>"` (hid it only at a ready check, Buffs.lua:1418) becomes `"pull:<m>"`, which only Before the pull reads
  (1.6). Nothing widens.

### 2.3 Hearing PallyPower: new `CuteAuras/PallySync.lua`

`local Ps = A.Part("PallySync", {...})`, in the toc after Comm.lua, before Assign.lua. It speaks PallyPower's wire format as
read from its source (AznamirWoW/PallyPower 09d5067, PallyPower_Camelot.toc "PallyPower Forever", Interface 16001). Its
LICENSE.txt is All Rights Reserved: no PallyPower code is copied.

Wire facts:

- Prefix `PLPWR`. Channels PARTY, RAID, INSTANCE_CHAT, WHISPER.
- Class index (PallyPowerValues.lua:249-257): 1 WARRIOR, 2 ROGUE, 3 PRIEST, 4 DRUID, 5 PALADIN, 6 HUNTER, 7 MAGE,
  8 WARLOCK, 9 SHAMAN.
- Blessing digit: 1 wisdom, 2 might, 3 kings; `0` or `n` none. 4 to 9 (Salvation, Light, Sanctuary and others not in
  Forever) count as none and `other + 1`.

Comm.lua:

- `Cm:Init` also registers `PLPWR` (`pcall(C_ChatInfo.RegisterAddonMessagePrefix, "PLPWR")`).
- `onMessage` sends `prefix == "PLPWR"` (after `plain()`) to `Ps.OnMessage(text, channel, sender)`. A nil text or sender
  after plain counts `secret + 1`. Nothing is read while not in a group.

Parsing (tolerant: a bad message changes nothing and raises no error):

| Kind | Pattern | Effect |
|---|---|---|
| `SELF` | `^SELF ([0-9a-fn]+)@([0-9n]+)` | Needs 12 or more slot chars and 9 or more row chars, else `bad + 1`. The sender must resolve to a PALADIN member. Ranks: slot pairs 1-3 (hex rank; talent ignored). Row: chars 1-9 (a 10-column build's tenth is ignored). The sender's whole class row is replaced, as PallyPower does (PallyPower.lua:1960). |
| `ASSIGN` | `^ASSIGN (.+) (%d+) (%d+)$` | one class cell |
| `MASSIGN` | `^MASSIGN (.+) (%d+)$` | every class cell |
| `PASSIGN` | `^PASSIGN (.+)@([0-9n]+)$` | a whole row |
| `NASSIGN` | entries split on `@`, each `^(%S+) (%d+) (%S+) (%d+)$`, `_` read as space | one member's blessing from one paladin |
| `CLEAR`, `CLEAR SKIP` | | from a leader or assist: drop every PallyPower-set cell; else ignored |
| `REQ` | | answer (2.6) |
| `FREEASSIGN ...` | | stored for the diag only |
| `ASELF`, `AASSIGN`, `PPLEADER`, unknown | | `other + 1` |

Names in ASSIGN, MASSIGN, PASSIGN and NASSIGN resolve with `R.SenderMember`; a name that is no paladin in the group counts
`unsure + 1` and changes nothing. Who may set a paladin's cells: that paladin (its sender resolves to it), or
`A.Assign.MayChange(senderGUID, palGUID)` (leader or assist, as `As.SetOverride` checks). Else `refused + 1`. PallyPower's
receiver-side Free Assignment is not modelled.

State:

- `Ps.pals[guid] = { ranks = { wisdom, might, kings }, at, free }`: paladins heard sending SELF, unless their H1 says
  they run Cute Auras without PallyPower (2.5).
- `Ps.row[guid][CLASS] = { key or false, stamp }` and `Ps.member[palGUID][memberGUID] = { key or false, stamp }`: cells
  for paladins in `Ps.pals`. Their own SELF fills the row; their own or their leader's ASSIGN, MASSIGN, PASSIGN change
  it; NASSIGN fills `Ps.member`.
- For a paladin running Cute Auras only, a leader's ASSIGN, MASSIGN, PASSIGN or NASSIGN is taken by **that paladin's own
  client**, and by no other: `As.Set(me, bucket, key, true)` for every bucket of that class (NASSIGN: the member's bucket
  when that member is alone in it); the 4th argument marks it `pp`. Digit 0 is `As.Set(me, bucket, nil, true)` (back to
  Cute Auras' choice). The cell is then that paladin's own hand-set cell: one stamp (its clock), sent as O1 with a 7th
  field `pp`. As.Mine (Assign.lua:306-313), As.Resend (Assign.lua:297-304) and Cm.Save keep only `ov.from == me`, so they
  keep and send it again like any cell you set, and every client takes it from that one O1.
- Why not on every client: PallyPower sends PASSIGN or ASSIGN only on Auto-Assign, Load Preset or a grid click
  (PROTOCOL.md), so a client that reloads or joins later would never hear it again, and each client would stamp it with
  its own GetServerTime(). Assign.lua:2 needs the same answer on every client.
- `CLEAR` from a leader or assist drops `Ps.row` and `Ps.member` on every client; each Cute Auras paladin clears its own
  cells marked `pp` (`As.Set(me, bucket, nil)`, sent as O1).
- After any change: `A.Assign.Changed()`. On GROUP_ROSTER_UPDATE: `Ps.Prune()`. On leaving the group: `Ps.Forget()`.
- Kept over a reload: `Cm.Save` writes `group.pp = { pals, row, member }` (rows as 9-char strings); `Cm.Restore` reads it
  under the same same-group rule and one-hour age.

### 2.6 Speaking to PallyPower (fixes P3)

Only on a Cute Auras paladin with PallyPower not loaded, in a group, Blessings on, and `Cm.WhyNoBlessings()` nil.

A batch of three messages on `PLPWR`, through the Comm queue (same 0.3 s pace, fight wait, lockdown retry):

1. `SELF <12>@<9>`. Slots: for wisdom, might, kings `string.format("%x0", math.min(rank, 15))` with rank
   `S.RankKnown(D.BLESS[k])`, or `nn` when 0 or Never'd (as `Cm.Known`); then `nnnnnn`. Row: for class 1-9, the digit of `As.bless[me][b]` for that
   class's largest bucket, else `n`. Exactly 27 bytes. A short SELF makes a PallyPower leader's Auto-Assign raise a Lua
   error (PallyPower.lua:4797-4803, `tonumber(nil)`), so the harness checks the format strictly.
2. `ASELF nnnnnnnnnnnnnn@0` (without it PallyPower.lua:5096 `HasAura` can index a nil `AuraInfo`).
3. `FREEASSIGN NO | SYMCOUNT <GetItemCount(21177)> | COOLDOWNS:n:n:n:n`.

When:

- After a REQ heard: one batch to the group within 3 s; REQs coalesce; at most one batch per 5 s. Always to the group,
  never a whisper. Not for a REQ from a Cute Auras peer whose H1 field 8 is `-` (our own asker: it has our H1 and O1).
- After the SELF text changes, debounced 5 s, at most one batch per 15 s, but only once any PLPWR message from a member
  has been heard in this group.
- A waiting SELF, ASELF or FREEASSIGN in the queue is replaced by the newer one, in its place (as H1 now is, 2.5).
- Never ASSIGN, MASSIGN, PASSIGN, NASSIGN, CLEAR or PPLEADER.

Asking: one client asks, the **asker**: the lowest GUID among the members running Cute Auras (you and `Cm.peers`); when
it leaves, the next. In a group, out of a fight, at most once per 30 s, the asker sends `REQ` when a paladin has been in
the roster 10 s with neither an H1 nor a SELF; when its Blessings tab opens; after a fight at most once per 5 minutes while
a PallyPower paladin is in the group (PallyPower loses messages the client refuses in a fight: ChatThrottleLib 32 drops
result 11).

Relay: PallyPower whispers its SELF and ASELF answer to the asker, unless the asker leads or it is a raid in an instance
(PallyPower.lua:1946-1952, 1618-1622). The asker sends each whispered SELF to the group on our prefix, through the Comm
queue: `P1|<sender as heard>|<the PLPWR text>`. Every client, the asker too (the game echoes it), parses a P1 as that
sender's PLPWR message, with the same checks; a P1 counts only when its own sender resolves to the asker, and a PLPWR
whisper itself is never parsed. So every client parses the same messages, and N Cute Auras clients cost one REQ, not N.

- More icons: Elixirs on in 5-man and Raid asks every fitting elixir you carry (3 at most). Quiet, Never and the chips
  limit it.

  the tab's top line and the diag say where the role came from.
- Kin groups and one flask at a time are Classic's rules; Forever may stack some. Until two are seen at once the bar asks
  only one of them.
- PallyPower changes almost daily (commits 2026-11-03 to 11-24). The parser ignores what it does not know; tests use the
  exact strings of commit 09d5067.
- Our SELF puts the owner in other players' PallyPower. A malformed SELF errors on their client: the format test is strict.
- Name forms on the live client are unconfirmed; the Names diag line shows them. A name that resolves to nobody means a
  PallyPower paladin is heard but gets no column.

  it, and never touches a cell the leader set.

  1618-1622). One asker relays it as P1; while the asker's chat is locked down the others hear it after the fight. A
  relay costs one message per PallyPower paladin per REQ, and a REQ goes at most once per 30 s.

  is offline or reloading when the leader clicks, the choice is lost, as it is for a PallyPower paladin.

  shows "Interface action failed because of an AddOn" (the harness only knows explicit secure frames).
